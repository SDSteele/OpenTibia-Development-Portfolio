# OpenTibia / OTServ Development Portfolio

## 🖥️ Overview

This repository documents my long-term hands-on experience developing, scripting, hosting, administering, and maintaining **OTServ/OpenTibia-based multiplayer server environments**.

My work with OTServ began as a personal technical project and evolved into a broad learning environment spanning **software development, scripting, databases, networking, Linux/server administration, configuration management, troubleshooting, and system maintenance**.

Over the years, I worked with multiple generations of the OpenTibia ecosystem, from older server versions such as **8.4** and legacy client/bot environments through newer **The Forgotten Server / Canary-based** environments.

This repository preserves and organizes that work as a technical portfolio.

# 🔐 Security Perspective

Although these projects were originally developed around multiplayer game-server environments, they provided practical exposure to many concepts that are relevant to modern IT and cybersecurity.

Operating an Internet-facing server requires consideration of:

* Network exposure
* Authentication
* Access control
* Database security
* Input handling
* Client/server trust
* Configuration security
* Service availability
* Logging and troubleshooting
* Patch and version management
* Abuse and unauthorized access

This experience contributed to my broader interest in **systems security, penetration testing, and incident response**.

# 📚 Why This Matters

My OTServ experience represents an important part of my technical development because it required me to learn by **building and operating complete systems**.

Rather than learning programming, networking, databases, and Linux independently, I encountered them as interconnected pieces of a functioning environment.

A typical problem could require investigating:

**Code → Configuration → Script → Database → Network → Operating System**

That experience taught me to troubleshoot systematically, understand dependencies, read unfamiliar code, experiment safely, and continue working until a system functioned as intended.
